# 成果提出の動作と制限事項

[README](../README.ja.md) · [English](USAGE-LIMITATIONS.md)

## done の対象と差分

`waw done` の提出先は、孫からでも大元 `waw` です。対象は `/waw` 直下にあり、大元にも存在し、その子の開始 ref が記録された repo です。

提出ごとに各 repo の対象差分を squash し、再提出は前回成功分を基準にします。子だけに追加した repo や、依存する祖先の未提出変更は自動で取り込みません。競合せず適用できた変更にも統合後の試験が必要です。

## 競合と部分失敗

統合対象の dirty や Git 操作中は提出を拒否します。競合は子の提出準備 branch に残ります。内容を修正して stage し、`git cherry-pick --continue` を完了してから `waw done` を再実行してください。提出準備と、元の作業 branch での追加開発を混ぜないでください。

大元への最終反映は fast-forward のみです。自動 reset / stash / rollback はなく、複数 repo の提出も atomic ではありません。途中失敗した場合は、診断と各 repo の状態を確認してから再実行します。

## 環境の保持と削除

`waw done --keep` は提出後の保持を要求します。子孫・mount 依存・対象外 repo がある場合も環境を保持します。それ以外では、Git 管理外の子ローカルなデータや無視されたビルド成果物もコンテナとともに消え得ます。

`waw drop` は、所有・依存検査は行いますが、未提出 commit・未コミット変更を確認や退避なしで破棄します。重要なデータはバックアップしてください。単に退室する `exit` なら環境を残し、`waw bash <ID>` で再入室できます。

`waw temp` は終了・失敗・処理可能な割込み後に削除を試みますが、SIGKILL やホスト停止では保証しません。残存環境は `waw list` で確認してください。共有領域や外部への書込みは巻き戻りません。

## コピー・共有状態・ホスト連携

- RAM や実行中プロセスはコピーしません。稼働中コピーは crash-consistent に留まり、DB 等にはアプリ側で書込みを止めるなどの対応が必要です。子で必要なプロセスは起動し直します。
- `/root` のツール・キャッシュは共有です。新しい子は `/waw/waw-root` から大元の `/waw` を読み取れます。未信頼コードを安全に隔離する sandbox ではなく、`incus-admin` はホスト root 相当です。
- 大元を置き換えても既存 mount は自動移行しません。
- 端末操作、PowerShell の名前付き引数・native 終了コード伝播には制限があります。
- copy-on-write でも並列ジョブの CPU・RAM・I/O は共有し、書込みに応じてディスクを消費します。

## 確認済みの範囲

既存の開発環境では fork → 編集・試験 → commit → done、Windows UNC 編集、PowerShell 往復の実機記録があります。専用 Ubuntu 環境では孫から大元への直接提出、子側での競合解消、再提出、一時環境の操作も確認しています。

過去の詳細記録は内部の開発 repo に保持しています。今回の候補は[既存環境での install・動作確認](VERIFICATION.md)を参照してください。通常 `done` 後の子の自動削除も確認しています。

新規環境の検証ではなく、bootstrap は mock 試験までです。複数 repo の部分失敗からの再実行と `done --keep` には、実 Incus での一通りの確認が残っています。

内部の開発 repo では `ria check` / `ria test` を実行します。開発用ルート Riafile と test はこの配布物には含めていません。構文・差分とローカル処理を検査しますが、mock を含むため Windows / Incus の実機試験の代わりにはなりません。
